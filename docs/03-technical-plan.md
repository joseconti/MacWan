# Technical plan — MacWan

> Phase 2 artifact, **DRAFT v0.1 (2026-10-06)**. The code map in §3 is a **TARGET tree**: no path
> exists until a slice creates it (all paths are unmarked = to build). Spikes in §9 come first and
> may change §2–§6; record every change in `docs/decisions.md`.

## 1. Stack

| Layer | Choice | Why |
|---|---|---|
| App | Swift 6, SwiftUI, Observation (`@Observable`), Swift Concurrency | native, accessible, José's requirement |
| Min target | macOS 14.0, arm64 only | MLX + MPS bf16 maturity; Apple Silicon only |
| Project | Xcode project generated by **XcodeGen** (`project.yml`) + SwiftPM packages for modules | reviewable diffs, no hand-edited pbxproj |
| Persistence | SwiftData (jobs, renders, installed models) + JSON files for catalogue/recipes | simple, local |
| Video | AVFoundation (playback, thumbnails, export/transcode) | no extra deps |
| Updates | Sparkle 2 (EdDSA-signed appcast) | standard for notarized non-App-Store apps |
| Python runtime | bundled `uv` binary → python-build-standalone CPython 3.12 → per-engine venvs from shipped `uv.lock` | reproducible, no system deps |
| Engine MLX | `mlx`, `mlx-video` (pinned git SHA), `mlx-lm`/`mlx-vlm` for assistant | fastest on Apple Silicon |
| Engine MPS | `torch` (MPS), `diffusers`, `transformers`, `accelerate`, `gguf`, `imageio-ffmpeg` | tasks MLX lacks |
| Downloads | `huggingface_hub` inside the worker (resume, revision pinning, `HF_HUB_ENABLE_HF_TRANSFER` VERIFY), ModelScope fallback | robust large-file downloads |
| Lint/format | SwiftLint, swift-format; ruff for Python | |
| Tests | Swift Testing + XCTest/XCUITest; pytest for worker | |

## 2. Architecture

```
┌──────────────────────────── MacWan.app (sandbox off, hardened runtime) ───────────────────────────┐
│ SwiftUI views ─► ViewModels (@Observable) ─► Services                                              │
│   Onboarding · Create(task screens) · Queue · Library · Models · Settings                           │
│ Services: HardwareProbe · RuntimeManager · ModelManager · Catalogue · JobQueue · EngineHost         │
│           PromptAssistant · ExportService · SecretsStore(Keychain) · Updater(Sparkle) · Logger      │
│ EngineHost ── spawns/monitors ──► worker processes (one per engine), JSON-lines over stdio         │
└────────────────────────────────────────────────────────────────────────────────────────────────────┘
        │                                                                  
        ▼  ~/Library/Application Support/MacWan/ (or user-chosen volume for models/)
   runtime/uv, runtime/python/, runtime/venv-mlx/, runtime/venv-mps/, worker/ (copied from bundle)
   models/<model-id>/<variant>/…  shared/t5-umt5-xxl/<variant>/  shared/vae-2.1/  shared/vae-2.2/
   library/<render-id>/{video.mp4, thumb.jpg, recipe.json}   logs/   catalogue-cache.json
```

Key rules:
- **Engine abstraction.** `protocol InferenceEngine { capabilities; prepare(model:variant:); generate(recipe) -> AsyncThrowingStream<EngineEvent>; cancel(jobID) }`. Implementations: `MLXEngine`, `MPSEngine`, later `CloudEngine`. The UI never knows which engine runs a task; the **capability table** (catalogue + tier + measured benchmark) picks it.
- **The worker is ours.** `macwan_worker` (Python package in `Worker/`) wraps `mlx_video` and `diffusers` behind one command set. MacWan never parses third-party CLI output.
- **One render at a time**, warm model cache, idle unload after N minutes (setting).
- Memory guard: before a job, compare the variant's measured peak (from benchmark/catalogue) against `recommendedMaxWorkingSetSize`/physical memory; refuse with an explanation and suggest a smaller variant instead of letting macOS swap to death.

## 4. Worker protocol (JSON-lines, one object per line)

Command (app → worker, stdin):
```json
{"id":"c-123","cmd":"generate","job":"j-42","engine":"mlx","model":"wan2.2-ti2v-5b","variant":"mlx-q4",
 "task":"ti2v","params":{"prompt":"…","negative_prompt":"…","image":"/abs/in.png","width":1280,"height":704,
 "num_frames":121,"steps":40,"guide_scale":5.0,"shift":5.0,"scheduler":"unipc","seed":42,
 "loras":[{"path":"/abs/l.safetensors","scale":1.0,"target":"high"}]},"output":"/abs/library/r-9/video.mp4"}
```
Other commands: `probe` (versions, device, memory), `download` (repo, revision, files, dest),
`convert` (src, dest, dtype, quantize bits/group), `verify`, `load`, `unload`, `cancel {job}`,
`assistant {provider, kind: extend|caption|translate, text, image}`, `shutdown`.

Events (worker → app, stdout; logs go to stderr and a log file):
```json
{"job":"j-42","event":"phase","phase":"encoding_prompt"}
{"job":"j-42","event":"progress","step":12,"total":40,"elapsed_s":95.2}
{"job":"j-42","event":"preview","path":"/abs/tmp/p-12.jpg"}
{"job":"j-42","event":"done","output":"/abs/library/r-9/video.mp4","peak_mem_gb":21.4,"seconds":512.3}
{"job":"j-42","event":"error","code":"OOM","message":"…","recoverable":true}
```
Error codes (closed list): `OOM`, `MODEL_MISSING`, `INVALID_PARAM`, `CANCELLED`, `DOWNLOAD_FAILED`,
`CHECKSUM_MISMATCH`, `DISK_FULL`, `ENGINE_CRASH`, `UNSUPPORTED_ON_DEVICE`, `INTERNAL`.
Protocol is versioned (`{"cmd":"hello","protocol":1}` handshake); app and worker refuse mismatches.

  "defaults":{"steps":40,"guide_scale":5.0,"shift":5.0,"scheduler":"unipc"},

`disk_gb` / `peak_mem_gb` are `null` until measured in spikes — never invented. Initial models: all
rows of `docs/research/wan-video-ecosystem.md` §2 except Dancer; S2V and Animate-2 flagged
`"availability":"deferred"`.

## 6. Install & update sequence (RuntimeManager)

1. Copy bundled `uv` (signed, in `Contents/Helpers/`) to `runtime/uv` if version differs.
2. `uv python install 3.12 --install-dir runtime/python` (pinned patch version).
3. For each needed engine: `uv sync --frozen --project worker/locks/<engine>` into `runtime/venv-<engine>`.
4. Copy `Worker/` sources from the bundle to `runtime/worker/` (versioned dir) and run `probe`.
5. Record installed versions in `runtime/state.json`; Repair = delete venv and redo 3–4.
Each step is idempotent, logs to `logs/runtime.log`, and reports progress to the onboarding UI.
Network failures retry with backoff; partial venvs are discarded, never "half-used".

## 7. Security & privacy (desktop profile, derived from Keel web-app profile)

- Hardened runtime + notarization; sandbox off (documented decision). Entitlements minimal:
  `com.apple.security.cs.disable-library-validation` **only if** a spike proves it is required for
  the child Python process — VERIFY (the worker is a separate process, so likely not needed).
- Downloads only from an allow-list of hosts; HF revisions pinned in the catalogue; checksums
  (from HF `lfs.sha256`) verified before use.
- No `shell=True`, no string-built commands: `Process` with argument arrays; file paths validated to
  stay inside MacWan's directories.
- CLIs used by the assistant are run with fixed arguments and timeouts; their output is data.
- Keychain for secrets; logs scrub tokens and (by default) prompts.
- Threat model to be written at Phase 2 close: `docs/threat-model.md`.

## 8. Testing

- Swift: unit tests for Catalogue, Recipe validation (4n+1, sizes, divisors, fps ↔ duration),
  JobQueue state machine, protocol codec (golden JSON), RuntimeManager with a fake `uv`.
- Worker: pytest with a **fake engine** (deterministic events) for protocol tests; real-engine smoke
  tests marked `slow` running Wan2.1 1.3B (q4) at 832×480, 9 frames, 4 steps.
- UI: XCUITest for onboarding (fake runtime), create → queue → library with the fake engine.
- Accessibility: XCUITest `performAccessibilityAudit()` per screen; manual VoiceOver pass guided.
- Test-first policy (proposed): `pure-logic` (Keel default).
